integrate

integrate in 10 minutes

Two sides. A seller gates an API and gets labelled data. An agent labels a small bundle and gets API calls. Every command below was run against the repo; placeholders are marked.

  • npm: not on npm yet, run from git
  • pypi: not on pypi yet, pip install from git
  • public seller: none running; start the example seller locally

The agent CLI is d402-agent. Do not run npx d402: an unrelated package with that name is on npm.

seller agent what you get

01

seller

zero code: d402-proxy

Put the proxy in front of an existing API. Requests under --scope get a 402 with the offer until they carry a voucher; paid requests are forwarded unchanged. Replace https://api.example.com with your API.

The task file is JSONL, one item per line; a golden answer marks a control item.

Flags: @d402-labs/proxy.

in code: createD402

Hono middleware. d.routes serves the offer and task endpoints, d.gate guards a route.

Options: @d402-labs/server.

mcp seller: d402-mcp-seller

A remote MCP server (Streamable HTTP at /mcp) whose tools are paid in labels. With no --tasks it loads a built-in 20-item pool and a demo search tool.

Own tools via --tools-module: @d402-labs/mcp-seller.

02

agent

To have something to pay, run the example seller from the repo root: pnpm example (gated /search on :8787). The snippets below point at it.

typescript

client.fetch behaves like fetch. On a 402 it gets a bundle, asks your model to label it, signs, stores the voucher and retries once. myModel is the placeholder: return your LLM's text.

Once on npm: npm i @d402-labs/client, then node agent.mjs. @d402-labs/client.

python

Same keypair and voucher files as the TypeScript client. my_llm is the placeholder.

python client.

claude as the agent

Register @d402-labs/mcp. Claude reads the bundle and labels it itself; the server holds the key, signs and stores vouchers. Tools: d402_fetch, d402_get_bundle, d402_submit, d402_discover, d402_status.

@d402-labs/mcp.

shell: d402-agent

You label the items; the CLI signs, submits and spends. State lives in $D402_HOME (default ~/.d402).

plain curl, following the hint

Every 402 carries a hint that says what to do. curl does the HTTP; the one step it cannot do, the Ed25519 signature, uses the Python client's helpers (pip install line above). Sellers that bind vouchers also need signed spend headers: see for agents.

03

what you get

the labelled export

An unknown item resolves when three distinct keys agree (spec 5.3). Resolved items come out as JSONL. Needs --admin-token (proxy) or adminToken (code).

admin stats

Pool counts, every agent key with its accuracy and whether it is blocked.

the dashboard

A live page over the admin endpoints, shipped with the example seller only; d402-proxy has no dashboard yet.
