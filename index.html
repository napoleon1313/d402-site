d402

pay for api access with labelled data instead of money.

The same 402 handshake as x402, with a second way to pay. The agent labels a bundle of items for the seller. Some of them are hidden control items with known answers, and the agent is never told which. Pass them and the seller issues a voucher worth N calls. The seller gets a labelled dataset. The agent needs no wallet.

01

how it works

  1. 01

    step 1: ask

    The agent requests a gated route. The seller returns 402 with an offer: accepts lists d402 (and optionally USDC), tiers (5, 25 or 50 items for 10, 60 or 150 calls), scope, task URL, and a one-sentence hint telling an agent what to do.

  2. 02

    step 2: identify

    The agent sends its Ed25519 public key and asks for a bundle at a tier.

  3. 03

    step 3: bundle

    The seller builds the bundle. Some items are golden (known answers), the rest are unknown. Shuffled. The agent is never told which is which.

  4. 04

    step 4: label

    The agent labels every item, signs the bundle id plus the canonical JSON of its answers, and posts them.

  5. 05

    step 5: grade

    The seller grades the goldens. 80% or better (and 1 of 1) passes. On pass, the unknown answers become weighted votes and the seller mints a JWT voucher with N calls stored server side. On fail, nothing, and the agent's accuracy drops.

  6. 06

    step 6: spend

    The agent retries the route with the voucher. The seller decrements, serves, and returns D402-Calls-Remaining. When the calls run out, the agent earns again.

03

what agents pay with

Ranked by value per label, with the human precedent. v1 ships classification; pairwise, extract and telemetry are reserved task types.

  1. 01 pairwise preference chatbot arena. labs pay dollars per comparison
  2. 02 search relevance google raters
  3. 03 classification what v1 ships: urgency, topic, sentiment, moderation
  4. 04 extraction to a schema price, address, attributes out of a page
  5. 05 entity matching same product, same company, across two records
  6. 06 ocr and transcript correction recaptcha v1
  7. 07 translation checks duolingo
  8. 08 telemetry on the api itself error reports, schema mismatches, latency
  9. 09 the query itself waze

04

three ways in

01seller with an existing api

Gate any API with one command. No code.

02agent in claude code or claude desktop

Five MCP tools. The model is its own solver.

03human at a terminal

Earn a voucher once, then fetch with it.

04site with no data of its own

Labelling work leased from a pool. Labels go back to the vendor who posted it.

Packages are not on npm yet. Until they are, run pnpm build and use the bins from packages/*/dist. quick start

05

built for agents, in the sponsors' words

  • x402

    About 892 million x402 transactions, from “roughly a thousand-ish buyers”.

    The rails exist. Almost no agent has a wallet. d402 is one more payment pattern in the same accepts array.

    from the hackathon talks

  • inkbox

    Agents sign up for themselves, and their identity should move between harnesses.

    The identity is an Ed25519 keypair in a file. It works in the TS client, the Python client and the MCP server, and the seller's trust score follows it.

    from the hackathon talks

  • primitive

    Agents are the primary customer. Design for them, watch them, ask them.

    Every 402 carries a one-sentence hint, so an agent that has never seen d402 knows what to do.

    from the hackathon talks

  • blaxel

    Build something “people will never want”.

    Humans hated CAPTCHAs. Nobody will label 5 support tickets to read a page. An agent does it and doesn't mind.

    from the hackathon talks

06

what is shipped

  • spec/SPEC.md The protocol. Read this first. docs
  • @d402-labs/spec Zod schemas, header names, defaults, Ed25519 signing helpers. docs
  • @d402-labs/server Hono middleware for sellers: offer, bundles, grading, trust, vouchers. SQLite via node:sqlite. CLI d402-tasks. docs
  • @d402-labs/client Fetch wrapper for agents: earns on 402, caches vouchers, retries. Pluggable solver. docs
  • @d402-labs/mcp MCP server so an LLM agent is its own solver: d402_get_bundle, d402_submit, d402_fetch, d402_status, d402_discover. docs
  • @d402-labs/proxy d402-proxy: put a d402 gate in front of any existing API with one command. No code. docs
  • @d402-labs/mcp-seller d402-mcp-seller: the seller as a remote MCP server. Tools paid for in labelled data; one voucher works on HTTP routes and MCP tools. docs
  • @d402-labs/pool d402-pool: the task marketplace. Vendors post labelling work, any site gates its API with it, the pool resolves labels across sites. docs
  • clients/python Python client with the same keypair and voucher files as the TS client. Signatures verified byte-equal. docs
  • clients/curl The whole protocol in a bash script: curl, jq and one signing call. docs
  • examples/search-proxy A gated search API with a live dashboard for demos. github
  • examples/site-review A job marketplace: agents pay for one API with any listed job. github
  • use-cases/ Runnable stories, from dataset builder to marketplace. docs
  • bench/ Simulated agents against hidden ground truth. Produces the 6 go/no-go numbers. docs
