package / @d402-labs/x402

@d402-labs/x402

x402 for d402 sellers. One 402 offers two ways to pay: label a few items (d402) or pay USDC (x402 exact, an EIP-3009 transferWithAuthorization signed by the agent). USDC payments are verified and settled through an x402 facilitator before the route runs.

Built on Coinbase's x402 v1 SDK (x402 on npm). The accepts entry is a standard x402 v1 PaymentRequirements, the credential is the X-PAYMENT header, and a settled request comes back with X-PAYMENT-RESPONSE, the same wire format as x402-hono.

Seller#

ts
import { createD402 } from "@d402-labs/server";
import { createX402Scheme } from "@d402-labs/x402";

const d402 = createD402({
  sellerId: "api.example.com", taskUrl: "https://api.example.com/.well-known/d402/tasks",
  scope: ["/search"], secret: process.env.D402_SECRET!, labels: ["pos", "neg"],
  schemes: [createX402Scheme({ payTo: "0xYourAddress", price: "$0.007", network: "base-sepolia" })],
});
app.route("/", d402.routes);
app.use("/search", d402.gate);   // voucher -> d402; X-PAYMENT -> x402; neither -> merged 402

The 402 body then holds x402Version: 1 and accepts: [ {scheme: "d402", ...}, {scheme: "exact", network, maxAmountRequired: "7000", asset: , payTo, resource, extra: {name, version}, ...} ]. With the proxy: d402-proxy --upstream --tasks t.jsonl --x402-pay-to 0x... --x402-price '$0.007' --x402-network base-sepolia.

Options: payTo, price ("$0.007" or 0.007 USD, converted to USDC atomic units), network ("base-sepolia" default, "base", other x402 v1 EVM networks), facilitatorUrl, createAuthHeaders (per-call facilitator auth, for the CDP facilitator), description, mimeType, maxTimeoutSeconds, resource(ctx) (default the request URL; set it when you sit behind a proxy), fetch (used for facilitator calls; tests inject a fake), settle (default true; false verifies only).

Failures never throw: a rejected, unsettled or unreachable payment returns 402 payment_failed with schemeError: { scheme: "x402", error, message }, where error is the facilitator's reason (insufficient_funds, ...), invalid_payment for a malformed header, or unexpected_verify_error / unexpected_settle_error when the facilitator cannot be reached.

Settlement happens before the route runs (the d402 gate verifies, then calls next()), so a route that fails after payment has still been paid for. x402-hono settles after the handler and skips settlement on a 4xx/5xx.

Agent#

x402-fetch (v1) zod-parses every accepts entry and throws on the d402 one, wherever it sits. Hand it a base fetch that drops entries it cannot read:

ts
import { createSigner, wrapFetchWithPayment } from "x402-fetch";
import { PaymentRequirementsSchema } from "x402/types";
const onlyX402: typeof fetch = async (u, i) => { const r = await fetch(u, i); if (r.status !== 402) return r;
  const b = await r.json(); b.accepts = b.accepts.filter((a: unknown) => PaymentRequirementsSchema.safeParse(a).success); return Response.json(b, { status: 402 }); };
const pay = wrapFetchWithPayment(onlyX402, await createSigner("base-sepolia", process.env.AGENT_KEY!));
const res = await pay("https://api.example.com/search?q=x");   // 200, X-PAYMENT-RESPONSE set

@x402/fetch (the maintained v2 SDK) pays the merged body as served, no shim:

ts
import { wrapFetchWithPayment, x402Client } from "@x402/fetch";
import { registerExactEvmScheme } from "@x402/evm/exact/client";
import { privateKeyToAccount } from "viem/accounts";
const client = new x402Client();
registerExactEvmScheme(client, { signer: privateKeyToAccount(process.env.AGENT_KEY as `0x${string}`) });
const res = await wrapFetchWithPayment(fetch, client)("https://api.example.com/search?q=x");

Settle for real on a laptop#

The tests in this package ran in a container with no route to x402.org, Base RPCs or Coinbase. Settlement was verified against an injected fake facilitator only (the request bodies it received are pinned in src/x402.test.ts, and match what the SDK's own useFacilitator sends). To settle on Base Sepolia:

  1. Make two keys, one for the seller (only its address is used) and one for the agent: cast wallet new (Foundry), or node -e 'const a=require("viem/accounts");const k=a.generatePrivateKey();console.log(k,a.privateKeyToAccount(k).address)'.
  2. Fund the agent address with Base Sepolia USDC from the Coinbase faucet (https://portal.cdp.coinbase.com/products/faucet, or https://faucet.circle.com). The facilitator pays gas, so the agent needs USDC, not ETH. Base Sepolia ETH from the same faucet is only needed if you also want to send transactions yourself.
  3. Set env and run a seller with the snippet above (payTo = seller address) and an agent with either agent snippet:
    sh
    export SELLER_ADDRESS=0x... AGENT_KEY=0x... D402_SECRET=$(openssl rand -hex 16)
  4. The agent's response carries X-PAYMENT-RESPONSE; decode it with decodeXPaymentResponse (from x402-fetch or x402/shared) and look the transaction up on https://sepolia.basescan.org.

The default facilitator is https://x402.org/facilitator (the SDK's default; it serves testnets). For network: "base" (mainnet USDC 0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913) use Coinbase's CDP facilitator: the @coinbase/x402 package exports a facilitator config whose url and createAuthHeaders go into facilitatorUrl and createAuthHeaders here (it reads CDP API keys from the environment; see its README).

Notes#

  • The SDK's useFacilitator always calls the global fetch, so this package carries a short port of it (same URL paths, headers and body) that takes an injectable fetch.
  • x402 v1 is deprecated upstream in favour of @x402/core (v2). v2 moves the challenge into a PAYMENT-REQUIRED header and uses CAIP-2 network ids (eip155:84532). v2 clients still pay v1 offers like this one.
  • Only EVM networks are supported. Solana exact needs a fee payer from the facilitator's /supported and is not wired.
