d402 client for Python

A minimal agent-side implementation of spec/SPEC.md sections 2-7.2: discover an offer, earn a voucher by labelling a bundle, and spend it through a requests wrapper that handles the 402 handshake for you.

Dependencies: Python 3.10+, cryptography, requests. No build step.

Project site: https://napoleon1313.github.io/d402-site/ . Source: https://github.com/napoleon1313/d402 .

Install from PyPI (once published)#

The package is prepared for PyPI under the name d402 but has not been uploaded yet, so this does not work today. Once it is published:

sh
pip install d402              # gives you `import d402` and the `d402-agent-py` command
d402-agent-py --help
python
from d402 import D402Client, Keypair, llm_solver
client = D402Client(Keypair.load_or_create("~/.d402/keypair.json"),   # my_llm: prompt str -> reply str
                    solver=llm_solver(my_llm), cache_path="~/.d402")
res = client.fetch("http://localhost:8787/search?q=gpu")   # 402 -> earn -> retry
print(res.status_code, res.json())

For AI agents: the hint in the seller's 402 response plus d402.D402Client(...).fetch(url) is the whole integration. fetch reads the 402 offer, earns a voucher with your solver, retries, and caches the voucher for later calls. help(d402) prints the same in ten lines.

Release steps for maintainers are in RELEASING.md.

Install from the repository#

Either copy the d402/ folder next to your code, or:

sh
cd clients/python && pip install -e .     # gives you `import d402` and the `d402-agent-py` command

The TypeScript client's CLI is d402-agent (@d402-labs/client), not d402; both read the same $D402_HOME.

Usage#

python
from d402 import D402Client, Keypair, lookup_solver, llm_solver

keypair = Keypair.load_or_create("~/.d402/keypair.json")          # Ed25519, created on first run (0600)
solver = llm_solver(lambda prompt: my_llm(prompt))                # or lookup_solver({"i_1": "tech", ...})
client = D402Client(keypair, solver=solver, model="claude", cache_path="~/.d402")

res = client.fetch("http://localhost:8787/search?q=gpu")          # 402 -> earn (get bundle, solve, sign, submit) -> retry
print(res.status_code, res.headers["D402-Calls-Remaining"], res.json())

res = client.fetch("http://localhost:8787/search?q=ceasefire")    # cached voucher, no earning
for v in client.status():
    print(v.sellerId, v.jti, v.calls, "calls left")

fetch(url, method="GET", **requests_kwargs) returns a plain requests.Response. Lower-level pieces are there too: discover(base), get_bundle(task_url, tier), submit(task_url, bundle, answers), earn(accept, tier=None), and the signing helpers sign_submit, sign_spend, canonical_json. Protocol failures raise D402Error(code, message, status, body); an ordinary non-2xx from the gated route is just returned.

Command line#

Installed, the command is d402-agent-py; from a checkout without installing, python -m d402 runs the same thing.

sh
export D402_HOME=~/.d402                               # default; holds keypair.json and vouchers.json
d402-agent-py keygen                                   # prints the public key
d402-agent-py discover http://localhost:8787
d402-agent-py earn http://localhost:8787 --tier s --answers answers.json   # answers.json: {"i_1": "tech", ...}
d402-agent-py fetch "http://localhost:8787/search?q=gpu"
d402-agent-py status
d402-agent-py --version

earn and fetch take --answers (a lookup file) because the CLI has no LLM; in code you pass llm_solver. status prints jti, sellerId, calls, expiresAt and scope for each cached voucher, never the token, since the token is a bearer credential.

Shared identity and cache with the TypeScript client#

The file formats are identical to @d402-labs/client, so both clients can run as the same agent:

  • keypair.json is {"publicKey", "privateKey"} with base64url raw 32-byte keys, the file loadOrCreateKeypair(path) reads and writes.
  • cache_path pointing at a directory uses /vouchers.json, the file FileVoucherCache(dir) uses: {"version": 1, "vouchers": [{jti, sellerId, token, scope, calls, expiresAt, sub, taskUrl}]}. Writes are atomic (temp file + rename) and the file is re-read on every operation, so a voucher earned from Python is spent from TypeScript and vice versa. D402_HOME is the same convention the d402 MCP server uses.

canonical_json is json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False) and is byte-identical to the TS canonicalJSON for strings, ints, bools, null, lists and objects (the test suite checks both signatures against vectors generated by the TS implementation).

Bound spends (SPEC 7.1) are signed by default (sign_spends=True) and carry the SPEC 7.2 D402-Nonce (spend_nonce=True), the same as the TS client; sellers that do not bind vouchers ignore the extra headers. sign_spend(..., nonce=None) gives the 5-line form for a seller that predates 7.2.

Tests#

sh
cd clients/python && python3 -m unittest -v          # or: python3 -m pytest -q
pip install -e '.[dev]'                              # installs pytest

The integration tests start examples/search-proxy as a subprocess (needs node and the repo's node_modules); they are skipped when the repo is not there.
