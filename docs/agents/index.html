for agents

What an agent does when a seller answers 402 with d402 in accepts, byte for byte. The spec is the source of truth; section numbers below point into it. A plain-text version for models is at /llms.txt.

You do not have to implement this yourself: @d402-labs/client, the python client, @d402-labs/mcp and the d402-agent CLI do all of it. Snippets for each are on integrate.

the protocol#

The example values below are from a real run of clients/curl/walkthrough.sh.

1. read the offer (spec 3)

A gated route without a valid voucher answers 402. Pick the accepts entry with "scheme": "d402". The same body is at GET /.well-known/d402. Read hint if present: it is this page in one paragraph for that seller.

http
GET /search?q=rates HTTP/1.1
Host: api.example.com

HTTP/1.1 402 Payment Required
Content-Type: application/json

{ "d402": "1",
  "accepts": [ { "scheme": "d402", "sellerId": "api.example.com",
                 "taskUrl": "https://api.example.com/.well-known/d402/tasks",
                 "taskTypes": ["classify"], "scope": ["/search"], "voucherTtl": 86400,
                 "hint": "No wallet needed. To get 10 calls on /search: GET ...",
                 "tiers": [ { "id": "s", "items": 5, "est_tokens": 1000, "reward": { "calls": 10 } } ] } ],
  "error": "missing_voucher", "message": "D402-Voucher header is required" }

2. have a key (spec 2)

One Ed25519 keypair, made once and kept. D402-Key is the raw 32-byte public key in base64url without padding. Trust is tracked per key: a key with a clean history sees fewer control items per bundle (spec 5.2), and a key that answers them badly gets blocked.

3. get a bundle (spec 4)

GET {taskUrl}?tier={id} with D402-Key. D402-Model (your model family) is optional and helps sellers that require two model families to agree. The smallest tier is the cheapest way to get a first voucher.

http
GET /.well-known/d402/tasks?tier=s HTTP/1.1
Host: api.example.com
D402-Key: _SQ38g0-LOB6Z0dqnzLix4fDSGt2UkQ6PPzSxZjNXpQ
D402-Model: claude

HTTP/1.1 200 OK

{ "bundleId": "b_qZc60Px-mLxUXlQf", "tier": "s", "type": "classify",
  "instructions": "Label each news snippet with exactly one of: sports, business, tech, world.",
  "labels": ["sports", "business", "tech", "world"],
  "items": [ { "id": "i_00004", "text": "The home side drew the host nation in the semi-final after a late goal." }, ... ],
  "expiresAt": 1792310531 }

4. label every item (spec 8)

For classify, answer each item id with exactly one string from labels. Some items are control items with known answers; you are not told which, so label all of them as well as you can. Answers on the other items become votes in the seller's dataset. Some sellers also offer other task types; the bundle's type, instructions and the offer's hint say how to answer them.

5. sign and submit (spec 5)

POST {taskUrl}/{bundleId} with D402-Key and a JSON body {answers, model?, sig}. On 200 you get the voucher, a JWT worth calls calls on paths under scope until expiresAt.

http
POST /.well-known/d402/tasks/b_qZc60Px-mLxUXlQf HTTP/1.1
Host: api.example.com
D402-Key: _SQ38g0-LOB6Z0dqnzLix4fDSGt2UkQ6PPzSxZjNXpQ
Content-Type: application/json

{ "answers": { "i_00004": "sports", "i_00002": "tech", "i_00003": "world", "i_00143": "business", "i_00117": "business" },
  "model": "claude",
  "sig": "yy71BYX7OJVr19FHB_uee3ycXtL_jE4Q7Z9xdYzVaf-cf36yJMSJHbsALuZ1Hf5oIm5c9koTpGZuJg5__eUuDw" }

HTTP/1.1 200 OK

{ "voucher": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "calls": 10, "scope": ["/search"], "expiresAt": 1792396331 }

6. spend (spec 7)

Retry the original request with D402-Voucher. Every successful spend carries D402-Calls-Remaining. Keep the voucher and reuse it until the count reaches 0 or a spend answers 402 again; then go back to step 3.

http
GET /search?q=rates HTTP/1.1
Host: api.example.com
D402-Voucher: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

HTTP/1.1 200 OK
D402-Calls-Remaining: 9

signing formats#

Ed25519 over the UTF-8 bytes of these strings. \n is one newline byte (0x0a). The signature is sent as base64url without padding.

text
submit:            "d402:submit\n" + bundleId + "\n" + canonicalJSON(answers)
bound spend (7.1): "d402:spend\n" + METHOD + "\n" + path + "\n" + jti + "\n" + timestamp
with nonce (7.2):  "d402:spend\n" + METHOD + "\n" + path + "\n" + jti + "\n" + timestamp + "\n" + nonce
  • canonicalJSON: object keys sorted recursively, no whitespace. In Python: json.dumps(answers, sort_keys=True, separators=(",", ":"), ensure_ascii=False). The answers object you POST does not have to be sorted; only the signed bytes are.
  • METHOD is upper case. path is the request path without the query string.
  • jti is the voucher JWT's jti claim (decode the middle segment; no need to verify it).
  • timestamp is unix seconds as a decimal string, the same value as D402-Timestamp.

The exact bytes signed in step 5 above:

text
d402:submit
b_qZc60Px-mLxUXlQf
{"i_00002":"tech","i_00003":"world","i_00004":"sports","i_00117":"business","i_00143":"business"}

error codes and what to do#

Task endpoints answer { "error": code, "message": string }. A failed spend answers 402 with the offer body plus error and message, so the way to recover is always in the same response.

getting and submitting bundles (spec 4, 5)

errorstatusmeaningwhat to do
missing_key400No D402-Key header.Send your public key on both task requests.
bad_key400D402-Key is not a 32-byte Ed25519 public key in base64url.Encode the raw 32 bytes as base64url with no = padding.
bad_tier400The tier id is not in the offer.Use an id from accepts[].tiers.
no_tasks409Nothing to hand out, or no unknown item is left for your key.Do not loop. Try again much later or use another seller or another scheme.
rate_limited429Over 60 bundles per key per hour, 120 per IP per hour, or 5 open bundles per key.Wait Retry-After seconds. Submit or let expire the bundles you hold.
blocked403Your key answered control items badly: 5 or more bundles at an estimated accuracy below 0.6.This key cannot earn here again. Vouchers it already holds keep working until they expire.
unknown_bundle404The seller has no such bundle (wrong id or task URL, or the seller lost its state).Get a new bundle.
expired_bundle410Submitted after expiresAt (600 s by default).Get a new bundle and answer it sooner, or use a smaller tier.
bad_signature401sig does not verify for D402-Key and this bundle.Sign the exact submit string below with the same key you sent on GET. Check canonical JSON, real newline bytes, and base64url without padding.
already_submitted409This bundle was graded already.Use the voucher from the first submit; if you lost it, earn again.
incomplete400An item has no answer.Answer every item id in the bundle.
bad_label400An answer is not exactly one of labels.Copy the label string exactly, same case.
quality422Too few control items right (pass is at least 80%, and all of them when the bundle has one).Get a new bundle and label more carefully. The seller never says which items were wrong. Your accuracy estimate dropped.
bad_request400Body is not JSON or not {answers, sig}, or an unknown type parameter.Fix the request.

spending (spec 7)

errorstatusmeaningwhat to do
missing_voucher402No D402-Voucher header.Earn one (steps 2 to 5), then retry.
voucher_invalid402Not minted by this seller, malformed, or its jti is unknown here.Drop it and earn a new one.
voucher_expired402Past exp (voucherTtl after minting).Drop it and earn a new one.
voucher_exhausted402No calls left.Drop it and earn a new one.
scope_mismatch402The path is not under the voucher's scope.Use a voucher whose scope covers the path; the 402 on this route carries the offer for it.
bad_key402Bound seller: D402-Key missing or not the voucher's sub.Send the key the voucher was earned with.
stale_timestamp402Bound seller: D402-Timestamp missing or more than 300 s from the seller's clock.Send the current unix time in seconds; check your clock.
bad_signature402Bound seller: D402-Sig does not verify, the nonce is missing where the seller requires one, or the nonce is not 8 to 128 characters.Recompute the spend signature below; send a 16-byte base64url D402-Nonce.
replayed_spend402Bound seller: this (jti, nonce) pair was used already.Use a fresh nonce on every request.
payment_failed402You paid with another scheme (x402 X-PAYMENT, MPP Authorization: Payment) and it failed; schemeError says which.Fix that payment, or pay with d402 instead.

key-bound spends and the nonce#

By default a voucher is a bearer token: whoever holds it can spend it. A seller that sets bindVouchers (spec 7.1) also requires D402-Key, D402-Timestamp and D402-Sig on every spend, so a leaked voucher is useless without your private key. The timestamp must be within 300 seconds of the seller's clock.

That alone lets a captured request be replayed inside the 300-second window. Spec 7.2 closes it: send D402-Nonce (16 random bytes, base64url, new for every request) and sign the 6-line form. The seller remembers each (jti, nonce) and answers replayed_spend to a repeat. Sellers with requireSpendNonce reject bound spends without one.

The offer does not say whether a seller binds, so send the four headers on every spend. A seller that does not bind ignores them. The TypeScript and Python clients do this by default.

js
import { signSpend } from "@d402-labs/spec";
import { randomBytes } from "node:crypto";

// keypair: { publicKey, privateKey }, the key the voucher was earned with; voucher: the JWT string
const jti = JSON.parse(Buffer.from(voucher.split(".")[1], "base64url").toString()).jti;
const ts = Math.floor(Date.now() / 1000);
const nonce = randomBytes(16).toString("base64url");
const sig = signSpend(keypair.privateKey, "GET", "/search", jti, ts, nonce);
const res = await fetch("http://localhost:8787/search?q=rates", {
  headers: { "D402-Voucher": voucher, "D402-Key": keypair.publicKey,
             "D402-Timestamp": String(ts), "D402-Nonce": nonce, "D402-Sig": sig },
});

earn ahead of time and bank vouchers#

Nothing forces you to wait for a 402. GET /.well-known/d402 returns the offer, so an agent can earn while idle and spend later without a labelling detour in the middle of a task.

  • A voucher is valid only at the seller that minted it, on paths under its scope, until expiresAt (voucherTtl seconds, 86400 by default). Do not bank more than you will spend before then.
  • Bigger tiers pay more calls per item in the default tiers (s: 10 calls for 5 items, m: 60 for 25, l: 150 for 50), at more tokens per bundle.
  • Rate limits cap banking: 60 bundles per key per hour, 5 open bundles per key (spec 9).
  • Keep vouchers on disk: FileVoucherCache(dir) in TypeScript and cache_path=dir in Python share one vouchers.json, so either client can spend what the other earned.
js
// client from createD402Client({ keypair, solver, cache: new FileVoucherCache(dir) })
const offer = await client.discover("http://localhost:8787");      // GET /.well-known/d402
const accept = offer.accepts.find((a) => a.scheme === "d402");
await client.earn(accept, "m");                                     // 25 items -> 60 calls, cached
console.log(await client.status());                                 // every banked voucher
python
offer = client.discover("http://localhost:8787")
accept = next(a for a in offer["accepts"] if a["scheme"] == "d402")
client.earn(accept, tier="m")
for v in client.status():
    print(v.sellerId, v.calls, v.expiresAt, v.scope)
sh
d402-agent earn http://localhost:8787 --tier m --solver-cmd "python solve.py"   # bundle JSON on stdin, answers JSON on stdout
d402-agent status
